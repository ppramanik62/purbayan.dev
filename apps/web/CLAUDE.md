# CLAUDE.md — apps/web

React 19 + Vite + TypeScript portfolio, designed as a paper notebook.

## Commands

```bash
bun run dev           # dev server
bun run build         # typecheck then vite build
bun run typecheck     # type-check only
bun run preview       # preview production build
bun run sync:github   # refresh the GitHub snapshot (needs `gh` logged in)
bun run og:posts      # draw thumbnails for posts that lack one
```

## Architecture

**Routing:** React Router DOM v7, all routes in `src/App.tsx`. The tabs are `/`, `/projects`, `/experience`, `/writing`, `/reading` and `/open-source`. Old `/blog`, `/blog/:slug`, `/about` and `/projects/:slug` links redirect.

**Layout:** `src/components/layout.tsx` draws the notebook: the dated header, the red margin rule and the footer. Pages are built from `Row` in `src/components/notebook.tsx`, a margin note beside the writing. Below 680px the margin note stacks on top.

**Data:** everything the site says lives in `src/data/`. No CMS, no runtime API calls.

- `site.ts`: the home intro (the age is worked out from the birthday), the open-to-roles line, the database-papers notes.
- `open-source.ts`: hand-written.
- Content you edit as JSON in `src/content/`, never in the TS. Each TS file loads its JSON and checks it with the helpers in `src/data/parse.ts`; a bad entry fails the build with the path of the broken field.
  - `reading.ts` ← `reading.json`: sections of items, each with `title`, `url`, `kind` (`book`, `paper` or `article`, shown in the margin) and `tags`. No dates.
  - `experience.ts` ← `experience.json`: jobs, newest first, each with `company`, `url`, `role`, `period` (shown in the margin), `summary` and `work` bullets.
  - `social-links.ts` ← `social-links.json`: `github`, `linkedin`, `x` and `email`, each with `url`, `label` and `display`. All four keys are required because the pages use them by name.
- `open-source.ts`: which projects appear on /open-source. Their PRs, states and dates come from `github.json`.
- `projects.ts`: which repos appear on /projects. Their order, dates, descriptions and stars come from `github.json`.
- `github.json`, `public/avatar.png` and `public/oss/*.png` (org icons): generated by `bun run sync:github` (`scripts/sync-github.ts`). Don't edit by hand; rerun the script.

**Home "Recently":** the latest 3 projects, posts and open-source PRs, all derived from the data above. The latest post shows its thumbnail.

**Post thumbnails:** `bun run og:posts` (`scripts/og-posts.ts`) draws `public/og/<slug>.png` for any post that lacks one, using a local Chromium. Pass `--force` to redraw all.

**Automation:** `.github/workflows/sync-github.yml` runs the sync and the thumbnails daily and commits only when something changed.

**Blog posts:** Markdown in `src/content/blog/`, named `<yyyy-mm-dd>-<slug>.md`. The filename is the only place the date lives; the slug (date stripped) is the URL, `/writing/:slug`, and the thumbnail name, `public/og/<slug>.png`. `src/data/post-file.ts` parses the name for both `src/data/blog.ts` and `scripts/posts.ts`, and a bad name, an impossible date or a repeated slug fails the build. Required frontmatter: `title`, `tags`, `summary`, `readingTime`.

**Images:** a line on its own, `![alt](/blog/<slug>/name.svg "optional caption")`. Files live in `public/blog/<slug>/` (svg, png, jpg, webp, avif or gif; tldraw and Excalidraw drawings go in as SVG). `src/data/post-image.ts` parses the line; the site rejects missing alt text or a path outside the post's folder, and `scripts/posts.ts` fails the build when the file doesn't exist. The caption shows under the image. `src/components/blog/post-figure.tsx` draws it: clicking the image opens it larger in a native `<dialog>` (Esc or a backdrop click closes it); the expand icon shows on hover, and always on touch screens. Wide images scroll sideways in the modal on phones.

**Dividers:** `---` on a line of its own draws a short rule between parts of a post.

**Lists and tables:** `- item` or `1. item` lines make a list (numbers count from 1 whatever you type; a list is all dashes or all numbers). Items indented with spaces form a sub-list under the item above, one level deep. A table is `| a | b |` lines with a `|---|---|` line under the header; every row needs the header's cell count or the build fails. Cells use inline text; a `|` can't appear inside a cell. A `# ` line fails the build: the title comes from frontmatter, so headings in the body are `## `, with `### ` for a smaller subheading.

**Contents:** every heading gets a number (`§2`, `§2.1`) shown in red in the margin. A post with 3 or more headings also gets a table of contents (`src/components/blog/post-outline.tsx`). From 1280px wide it's a strip of divider tabs beside the page, one per `## ` section, each as tall as its share of the post; ticks inside a tab mark its `### ` subsections. The current tab sticks out and shows its title and subsections, and hovering another tab shows just its title. Narrower, it's a collapsed "Contents" list under the title. Heading ids come from their text (`src/data/blog.ts`), so `/writing/<slug>#<heading-id>` links to a section; the layout scrolls to it on load. Renaming a heading changes its link.

**Inline text** (`renderInlineText` in `src/lib/blog-rendering.tsx`, used for paragraphs, list items and sidenotes): `**bold**`, `*italic*` (oxfmt rewrites it as `_italic_` on commit; both work), `` `code` ``, `[^id]` sidenote references and `[text](url)` links. Links starting with `/` go through the router; anything else opens in a new tab.

**Sidenotes:** write `[^id]` in a paragraph or list item and `[^id]: the note` on its own line anywhere in the post. Notes are numbered by first use and sit in the margin beside their paragraph (under it on phones). A reference without a definition, or a definition never used, fails the build.

**Link previews:** `bun run build` ends with `scripts/prerender-posts.ts`, which writes `dist/writing/<slug>.html` with that post's title, summary and thumbnail in the meta tags, because link-preview crawlers don't run JavaScript. Cloudflare Pages serves those files directly and falls back to `index.html` for every other path through its single-page-app mode. Don't add a catch-all rule to `public/_redirects` or a top-level `404.html`: either one would hide the prerendered posts.

**Path alias:** `@` maps to `src/`.

## Styling

- Tailwind CSS 4. The palette is `--c-*` in `src/index.css`, exposed as `bg-paper`, `bg-card`, `text-ink`, `text-dim`, `text-faint`, `border-rule`, `text-pen` (red), `text-pencil` (blue), `bg-code`.
- Light only. No dark mode.
- Fonts: Newsreader (`font-serif`, the body) and Spline Sans Mono (`font-mono`, margin notes and labels), from `@fontsource-variable`. Code blocks use the system monospace (`font-code`).
- `ink-link` is the underlined link style. Use `cn()` from `src/lib/utils.ts` for conditional classes.
- `src/lib/syntax-highlighter.ts` emits `text-tokyo-*`, `text-primary`, `text-muted-foreground` and `text-secondary-foreground`; those colours are defined in `index.css` for the dark code block.

## Conventions

- No new dependencies without good reason. The stack is intentionally lean.
- Pages in `src/pages/`, shared components in `src/components/`, content in `src/data/`. Never hardcode content in components.
